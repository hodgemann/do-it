# To-do

Tasks use Markdown checkboxes. Section headings give their status; backlog subheadings give their area. Order within each section is the reading order.

## Do it

- [ ] (do it) Short title: what to build, the files and functions involved, the constraints, and how to tell it is done. Large items list their batches:
  - [ ] Batch 1: … (one small result that can be verified and leaves the project working)
  - [ ] Batch 2: …

## Low priority

Optional. Name the kind of work here (for example `Translate …` items) and in the project's `do it` settings. It ranks below every other suitable task. Like other work, it must be queued with the user's approval before a fresh-session "do it" starts it.

- [ ] Translate the new labels in the export dialog: `Export`, `Include downloads`.

## Decisions needed

These wait for the user's choice before anyone builds them.

- [ ] Decide … Choices: (A) …; (B) …; (C) …. Recommended starting point: …

## Backlog

Work to scope and queue; these items are not marked `(do it)`.

### Area one

- [ ] …

## Notes

Defects and notes the user left on specific places (a line of code, a screen), with file and line references. These get priority when suggesting the next "do it".

- [ ] Note: …
